1 ภาพรวมผลิตภัณฑ์

ปัญหา: ข้อมูลลูกค้ากระจัดกระจาย — ใบแล็บกระดาษ · เครื่องชั่ง BCA · นาฬิกา · CGM · แชท LINE โค้ชต้องจำเอง คำแนะนำเลยไม่ต่อเนื่องและพิสูจน์ผลไม่ได้

ทางแก้: ศูนย์กลางเดียวคือ Customer Profile ที่ทุกโมดูลเขียนเข้า/อ่านออก + ชั้น AI ช่วยแปลผล + ลิงก์สาธารณะให้ลูกค้ากรอก/เชื่อมข้อมูลเองได้

1 · Customer profile เป็นแกนกลาง
ทุกฟีเจอร์ต้องผูกกับ customers.id
2 · Evidence over vibes
ตัวเลขจริงจากใบตรวจ/อุปกรณ์ ห้ามเดา
3 · Wellness ≠ diagnosis
ผิดปกติ → "ปรึกษาแพทย์" ห้ามเคลมรักษา
4 · โค้ชเร็วขึ้น ไม่ใช่ถูกแทนที่
AI สรุป/จัดลำดับ · คนตัดสินใจ

4 ฟีเจอร์ (โมดูลต่อโมดูล)

4.1 Customer 360 — หัวใจของระบบ

รวมทุกอย่างของลูกค้า 1 คนไว้หน้าเดียว: identity + สถานะสุขภาพ + insight + timeline + แท็บ

แท็บเนื้อหาตาราง
Labs / Trendsผลเลือดทุกครั้ง + กราฟ + สถานะcustomer_records, customer_lab_values
Body Mapจุดผิดปกติบนภาพร่างกายcustomer_lab_values
BCAน้ำหนัก/ไขมัน/กล้ามเนื้อ/visceral/body-agemeasurements
Allergyผลทดสอบภูมิแพ้อาหารcustomer_allergy_tests, customer_food_allergens
CGMน้ำตาลต่อเนื่อง + มื้ออาหารcgm_profiles/readings/meals
Supplementsตารางวิตามิน + ความปลอดภัยคู่ยาsupplement_schedule, customer_supplement_safety
Pulseข้อมูลนาฬิกา + assessmentpulse_*, whoop_*
Notesโน้ตโค้ช (ปักหมุดได้)coach_notes

ย่อย: health score + insight rules · Med-Map report · เก็บรายงาน HTML ส่วนตัว (customer_report_html) · access control (เจ้าของ/ผู้รับมอบหมาย/downline) · view log

4.2 BCA Tracker + Health Age

  • BCA: บันทึกผลเครื่องชั่ง → เกจ + กราฟย้อนหลัง + แก้/ลบ + ออกรายงาน
  • เกณฑ์เดียวทั้งระบบ: lib/medical-status.ts (5 ระดับ traffic-light + ป้ายไทยตามเกณฑ์คลินิก) ใช้ทั้งเกจ v2 · BCA Scan Reveal · labs
  • Health Age (PhenoAge · Levine 2018): lib/bio-age.ts — 9 marker · โหมด hybrid เติมค่าที่ขาดด้วยค่าประชากรตามอายุ + ป้าย "ประมาณ" · Customer 360 โชว์เลขเฉพาะเมื่อมี CRP + RDW จริง

4.3 UP Pulse — Wearables & Assessment

Whoop (OAuth + CSV) · Apple Health (export.xml) · Google Fit (⚠️ deprecated) — โค้ชสร้าง invite → ลูกค้าเปิด /connect/[token] → ยินยอม → ดึงข้อมูล · แบบสอบถาม /intake/[token] → ประเมิน → รายงานรวมทุก provider + แชร์ผ่าน /r/[token]

4.4 CGM Analyzer

น้ำตาลต่อเนื่อง + มื้ออาหาร · เข้าถึงด้วย passcode ต่อ profile (RLS + SECURITY DEFINER RPC) · cgm_readings ใหญ่สุดในระบบ (~34k แถว)

4.5 NutriScan AI + Food Log

ถ่ายรูปอาหาร → Gemini Vision → มาโคร + ผลต่อน้ำตาล + คะแนนสุขภาพ + คำแนะนำ → บันทึกเข้า nutriscan_scans

4.6 Plate Planner + LINE Bot (น้องจาน)

จัดจาน Muscle-Centric (Dr. Gabrielle Lyon) · อาหารไทยไม่ซ้ำ · สร้างภาพจานด้วย AI (แคชใน Storage) · ตั้งค่าต่อลูกค้า · LINE bot ผูกกลุ่มกับลูกค้าแล้วส่งเมนู+วิตามินอัตโนมัติ 18:00

4.7 Check FORM — AI Prospect Analysis

โปรไฟล์ผู้มุ่งหวัง + DISC → Gemini วิเคราะห์: แนวทางเข้าหา · สัดส่วน product/business · บทสนทนาตัวอย่าง · roleplay · red flags → จับคู่คลิป STP (reasoning-based) · cache ใน checkform_records

4.8 Prospect / Lead Pipeline

Prospect List → แปลงเป็น Check FORM record · Health Check สาธารณะ (/check/[coachId]) → healthcheck_leads → ผูกเป็นลูกค้าได้

4.9–4.10 Program Designer · Admin & Platform

ออกแบบโปรแกรมรายบุคคล · จัดการผู้ใช้/role/downline · Backup–Restore · View-as · Auth (login/join/reset) + ระบบเชิญ

6 Non-Goals (จงใจไม่ทำ)

  1. ไม่เป็นเวชระเบียนโรงพยาบาล (EMR) และไม่วินิจฉัยโรค
  2. ไม่ทำ e-commerce / ตะกร้าสินค้าในระบบนี้
  3. ไม่เก็บคีย์ AI ของผู้ใช้ไว้บนเซิร์ฟเวอร์ (BYO เท่านั้น)
  4. ไม่เปิดข้อมูลลูกค้าข้ามสายที่ไม่ใช่ downline ของตัวเอง
  5. ไม่ทำแอปมือถือ native (ยัง) — เว็บ responsive
